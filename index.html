Install Nexurity in Claude Code

Nexurity is a security audit assistant for Claude Code. It audits code, servers and live websites, handles incident response, and writes a client-ready HTML report. Claude Code builds it for you from a single prompt.

Install

Three steps to start the build

  1. Get the kit

    The kit holds the installation prompt and the two base report templates. Nothing else is needed. Download it, or clone it if you use Git.

    No Git needed. Download the kit: Download nexurity-main.zip Unzip it, then go into the folder: 
    cd nexurity-main
    If Git is installed, clone the repository. It also makes pulling kit updates easier. 
    git clone https://github.com/ramzibougdar/nexurity.git
cd nexurity

  2. Open Claude Code in the folder

    claude

    In the desktop app, open the kit folder instead: nexurity, or nexurity-main if you downloaded the ZIP.

  3. Start the installation

    Send this as your first message:

    Read PROMPT.md and follow it

    Claude Code reads the prompt and starts stage 1. It stops at the end of every stage and waits for you to say it can continue.

The build

The 8 stages, and what you approve

Each stage ends with a check you review. Reply "go ahead" to continue, or ask for changes first.

  1. Stage 1Documentation and sourcesChecks the current Claude Code plugin format, fetches the ten sources read-only (with Git, or as archives without it), records their licences and exact versions.You approve: NOTICE.md, the sources summary and the list of missing tools.
  2. Stage 2Plugin skeletonCreates the folders, commands, agents and schemas, then installs the plugin locally.You approve: the tree and that /audit appears in Claude Code.
  3. Stage 2bBranding and report documentsAsks for your company identity and creates the two HTML report documents from the base templates.You approve: previews of both documents.
  4. Stage 3Start-up wizardBuilds the clickable question screens for /audit and /incident.You approve: a dry run of every screen.
  5. Stage 4SafeguardsAdds the hook that only allows read-only commands during an engagement, on your machine and over SSH.You approve: the results of 30 allow/deny tests, including bypass attempts.
  6. Stage 4bUpdate checkBefore every audit, compares sources and tools with the recorded versions and asks before updating anything.You approve: a simulated update and the /nexurity-update flow.
  7. Stage 5Pipeline and agentsRecon, scanners, hunters in parallel, independent verifier, incident forensics.You approve: the agents, the routing rules and a dry run of /audit-quick.
  8. Stage 6Report generationTurns findings into the HTML report, with every value from the target escaped.You approve: screenshots and the escaping tests.
  9. Stage 7TrialsRuns Nexurity against deliberately vulnerable targets: OWASP Juice Shop, DVWA, a misconfigured server and a fake incident.You review: the reports, false positives, missed flaws and token cost per mode.
  10. Stage 8 · laterContinuous integrationA GitHub Action that reviews pull requests and comments with confirmed findings.
Stage 2b

Branding setup

The base templates carry the Nexurity identity. The /nexurity-setup command asks the questions below, then Nexurity creates the two report documents itself. You never edit the HTML by hand. Run the command again at any time to change the branding.

QuestionChoices
Company nameKeep Nexurity, or type the issuing company's name
LogoKeep the Nexurity logo, or give the path to an SVG file
ColoursKeep Nexurity's, enter your own (primary, dark, background, accent), or extract them from a CSS, SVG or HTML file
FontsKeep Schibsted Grotesk and JetBrains Mono, other Google Fonts, or system fonts only
Contact detailsAddress, email, phone and website for the report footer
Default languageEnglish or French

Colours are checked for readability before they are saved. Logos are always embedded in the report, so each report stays a single file.

After installation

Your first audit

Type /audit. Nexurity first checks for updates to its sources and tools, then opens the wizard.

ScreenWhat you choose
EngagementCode, server, live website or several · full, diff, quick or targeted · client or internal
TargetFolder, Git URL or PR · local server or SSH host · website URL
ScopeAreas to cover, stack (or auto-detect) and depth
Client and reportClient profile and report language
ConfirmationFull recap, and confirmation that the client gave written authorisation

The report is saved with the evidence and findings in your audits folder:

~/audits/<client>/AUD-2026-001/
├── audit-config.json   # your wizard answers
├── evidence/
├── findings.json
├── log.md              # what was actually done
└── report.html         # the client report
The report is confidentialIt describes exploitable flaws in your client's systems. Send it directly to the client; don't publish it online.

Built in

Safety rules

Never changes the targetProposes fixes for code and configuration, never applies them.
Read-only on serversOnly an allowlist of read commands runs, locally or over SSH.
Passive on live sitesNo scanning, fuzzing, exploitation or brute force.
Content is dataInstructions hidden in code or logs are ignored and flagged.
Independent verificationA finding is always re-checked by a different agent.
Authorisation firstNo server, website or incident work without the client's go-ahead.
Secrets maskedOnly the first and last 4 characters ever appear.
No silent updatesEvery update is shown as a diff and needs your approval.
Help

Troubleshooting

Claude Code moved to the next stage without asking

Remind it: "Stop. PROMPT.md says to wait for my go-ahead at the end of each stage." Then ask it to show the checks for the stage it skipped.

A tool is missing during an audit

Nexurity asks whether to install it, continue without it or cancel. The report's "Tools" section only lists what actually ran.

The update check is slow or I'm offline

The check stops after 15 seconds and the audit continues. The engagement log notes "updates not checked". You can turn the check off with "check_updates": false in config.json.

A command was blocked during an audit

That's the safeguard hook. Only read-only commands are allowed while an engagement is active. If a legitimate read command is missing from the allowlist, add it in scripts/guard.py and re-run its tests.

I changed the logo or colours

Run /nexurity-setup again. It recreates both report documents and shows you a preview before saving.
